# CLAUDE.md — Дневник питания

## Коротко о проекте

PWA-дневник питания: пишешь, что съел, свободным текстом («150г сувид курица
грудка»), приложение примерно считает КБЖУ и складывает в итоги дня. Подсчёт
не «до крошки», а для регулирования питания.

Сначала позиция ищется в локальном справочнике (`food_products`), если не
нашлась — КБЖУ оценивает бесплатная модель OpenRouter (`:free`). Без ключа
приложение работает полностью, только по справочнику.

UI на русском, ставится на домашний экран iPhone как PWA.

## Технологический стек

- **React 19 + TypeScript + Vite** (`tsc -b && vite build`, линтер `oxlint`)
- **React Router v7 — HashRouter** (не BrowserRouter: на Cloudflare Pages не нужен
  редирект `/* → /index.html`, иначе цикл и ошибка 100324)
- **Supabase** (`@supabase/supabase-js`) — Postgres + Auth + RLS. Единственный бэкенд.
- **PWA**: `manifest.webmanifest`, иконки, apple-touch-icon. Service worker нет —
  офлайн-режим не делали осознанно.
- Внешних зависимостей кроме supabase-js и react-router-dom нет. State-менеджера
  нет — React-хуки и контексты. `esbuild` — только dev-зависимость для `npm run check`.

## Архитектура

Поток данных: `lib/api.ts` (CRUD к Supabase) → `context/DataContext.tsx` (снимок
справочника, записей за 180 дней и настроек + оптимистичные мутации) → страницы.

- **Кеш-first.** Начальное состояние читается из `localStorage`
  (`food_cache_<user_id>__<ключ>`), затем `refresh()` в фоне тянет свежее.
  Кеш привязан к аккаунту и стирается при смене пользователя (`lib/cache.ts`).
- **Оптимистичные мутации.** Добавление/удаление записи сразу меняет состояние,
  при ошибке откатывается.
- **Авторизация** — `context/AuthContext.tsx`: вход по email/паролю, регистрация
  только по коду-приглашению (RPC `check_invite_code` + триггер на `auth.users`
  в проекте-хозяине).
- **Тема** — `context/ThemeContext.tsx`: `light | dark | system`,
  `localStorage.theme`, атрибут `<html data-theme>` (выставляется и в `index.html`
  до загрузки бандла).

## Поток разбора еды

```
textarea → parse.ts → match.ts → (не нашлось) llm.ts → черновик → food_entries
```

1. **`parse.ts`** — строки, заголовки «Завтрак/Обед/Ужин/Перекус», граммы
   (`90г`, `0,5 кг`, `200 мл`), штуки (`2 яйца`, `1 стакан`, `1 ст. л.`),
   комментарий после запятой. Одна строка может содержать несколько позиций
   («борщ 300г и хлеб 50г»).
2. **`match.ts`** — нормализация, стоп-слова, грубый стемминг, Dice по токенам
   с допуском на опечатки (Левенштейн). Порог автовыбора — 0.55.
3. **`llm.ts`** — один запрос на все незнакомые позиции, строгий JSON,
   проверка `ккал ≈ 4Б + 9Ж + 4У` (±30%) в `nutrition.ts`. Ответ сопоставляется
   с позициями **по названию**, не по порядку.
4. Черновик: граммы и **приём пищи** редактируются, КБЖУ пересчитывается;
   можно выбрать другой продукт из кандидатов или ввести КБЖУ вручную.

Оценка ИИ запускается **только для ненайденных позиций**: автоматически после
разбора (если ключ настроен) и точечно кнопкой на конкретной позиции.

## Советы по питанию

`lib/advice.ts` считает подсказки локально по записям за 7/14/30 дней:
частые продукты, доля категорий в калориях, средний белок, дни перебора,
овощи/фрукты, регулярность. Ничего не отправляет в сеть.

Кнопка «Разобрать через ИИ» на странице «Советы» отправляет компактную сводку
(`buildSummary`) бесплатной модели и просит 3 совета — это единственный сетевой
вызов в этом разделе.

## Модель данных

| Таблица | Поля | Смысл |
|---|---|---|
| `food_products` | `name, aliases[], category, kcal, protein, fat, carbs, piece_grams, basis, source` | справочник, значения на 100 г |
| `food_entries` | `date, meal, name, grams, kcal, protein, fat, carbs, product_id, source, assumption` | записи; КБЖУ — снимок |
| `food_settings` | `target_kcal, target_protein, target_fat, target_carbs` | цели на день |

- RLS на всех таблицах: `auth.uid() = user_id`.
- `basis`: `ready` (готовый), `dry` (сухой вес), `raw` (сырой) — показывается
  в черновике, чтобы не путать 90 г сухих макарон и 90 г готовых.
- Удаление продукта обнуляет `product_id` у записей (`on delete set null (product_id)`),
  сами записи и их КБЖУ остаются.

## Важные факты / грабли

- **`\b` в JS не работает после кириллицы** (`\w` = латиница/цифры). В регулярках
  разбора вместо него `(?![а-яa-z])`. Из-за этого однажды не распознавались ни
  «Ужин», ни «90г».
- **Вес готового vs сухого.** «90 г макароны» трактуется как готовое блюдо, если
  пользователь не выбрал «макароны сухие». Разница в 2.5 раза — в черновике
  показывается basis.
- **Seed идемпотентен**: заливается только при пустой таблице; при `force`
  удаляются строки `source='seed'`, пользовательские и ИИ-продукты не трогаются.
  Три JSON-файла сливаются и дедуплицируются по `lower(name)` — иначе уникальный
  индекс завалит всю вставку. Дубликаты с уже существующими строками
  пропускаются.
- **Брендовые позиции** (`foods-brands.json`) — значения по типичной упаковке,
  состав у марок меняется; такие строки стоит сверять с этикеткой.
- **Ключ OpenRouter — только в `localStorage`** (`food_llm_key`, `food_llm_model`),
  в БД не пишется. В `food_settings` есть неиспользуемая колонка `llm_model`.
- **PostgREST отдаёт максимум 1000 строк.** Справочник сейчас меньше; при росте
  добавить пагинацию в `fetchProducts` (как `selectAll()` в соседних проектах).
- **Модалки — `createPortal` в `document.body`** + `interactive-widget=resizes-content`
  в `index.html`, чтобы клавиатура не прятала кнопки.
- **Даты — по локальной дате** (`todayKey()`), не через `toISOString()`.
- `npm run check` собирает `scripts/check.ts` через esbuild и прогоняет разбор
  на реальных примерах — быстрый способ проверить правки `parse.ts`/`match.ts`.
