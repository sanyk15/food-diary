# Дневник питания

PWA-дневник питания с примерным подсчётом КБЖУ по свободному описанию еды.
Сначала ищет блюдо в локальном справочнике, если не нашёл — оценивает
бесплатная модель OpenRouter.

Стек тот же, что в `rhythm` и `expense-tracker-web`: React 19 + TypeScript + Vite,
Supabase (Postgres + RLS), HashRouter, PWA. Внешних зависимостей кроме
`@supabase/supabase-js` и `react-router-dom` нет.

## Быстрый старт

```bash
npm install
cp .env.example .env.local     # подставь URL и publishable-ключ Supabase
npm run icons                  # PNG-иконки для PWA
npm run dev
```

### 1. Схема БД

Открой SQL Editor в **существующем** проекте Supabase (rhythm или
expense-tracker — free-план разрешает 2 активных проекта) и выполни целиком
`supabase/schema.sql`. Все таблицы с префиксом `food_`, поэтому ничего не
пересечётся с другими приложениями.

### 2. Справочник

При первом входе приложение само заливает базовую таблицу из
`src/data/foods.json` (~210 продуктов и блюд, значения на 100 г). Если что-то
не залилось — «Настройки → Перезалить базовый справочник».

Справочник можно править и пополнять в разделе «Справочник».

### 3. ИИ (необязательно)

1. Зарегистрируйся на [openrouter.ai](https://openrouter.ai) — карта не нужна.
2. Создай ключ в разделе Keys.
3. В приложении: «Настройки → ИИ для незнакомых блюд» → вставь ключ →
   «Обновить» список моделей → выбери бесплатную (`:free`) → сохрани.

Ключ хранится только в `localStorage` устройства и не уходит в БД.
Без ключа приложение работает полностью — только по справочнику.

## Как писать еду

```
Ужин
90г макароны со сливками и беконом и сыром, взял порцию поменьше
150г сувид курица грудка
1 мандарин
```

- Заголовки «Завтрак / Обед / Ужин / Перекус» задают приём пищи.
- Граммы: `90г`, `150 г`, `0,5 кг`, `200 мл`.
- Штуки: `1 мандарин`, `2 яйца`, `1 стакан кефира`.
- Текст после запятой считается комментарием и не ищется в справочнике.

Приём пищи можно поменять в черновике (селект у позиции) и позже — тап по
записи в дне → «Приём пищи».

## Архитектура

```
src/
  data/foods.json          # базовый справочник (seed)
  lib/
    api.ts                 # CRUD к Supabase, заливка seed
    parse.ts               # разбор свободного текста на позиции
    match.ts               # нечёткий поиск по справочнику
    llm.ts                 # OpenRouter: free-модели, оценка КБЖУ, советы
    advice.ts              # локальные подсказки + сводка для ИИ
    nutrition.ts           # масштабирование порции, проверка 4/9/4
    cache.ts               # localStorage-кеш, привязан к user_id
  context/
    AuthContext.tsx        # вход, регистрация по коду-приглашению
    DataContext.tsx        # снимок данных + оптимистичные мутации
    ThemeContext.tsx       # light / dark / system
  pages/                   # Home (день), Products, Advice, Settings, Login
supabase/schema.sql        # таблицы + RLS + индексы
```

Поток: текст → `parse.ts` → `match.ts` по справочнику → для незнакомых
позиций `llm.ts` → черновик с редактируемыми граммами → `food_entries`.

## Модель данных

| Таблица | Смысл |
|---|---|
| `food_products` | справочник, КБЖУ на 100 г, синонимы, вес штуки |
| `food_entries` | записи дневника; КБЖУ — снимок на момент записи |
| `food_settings` | цели по КБЖУ |

RLS на всех таблицах: `user_id = auth.uid()`. Регистрация — по коду-приглашению
(та же схема, что в `rhythm`).

## Деплой

Cloudflare Pages: build `npm run build`, output `dist`. Переменные окружения —
`VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.

## Важные факты

- **HashRouter**, а не BrowserRouter — иначе на Cloudflare Pages нужен
  редирект `/* → /index.html`, который зацикливается (ошибка 100324).
- **Даты — по локальному времени**, без `toISOString()`.
- **Кеш привязан к аккаунту**; при смене пользователя стирается.
- **PostgREST отдаёт максимум 1000 строк** — справочник сейчас меньше, но при
  росте стоит добавить пагинацию в `fetchProducts`.
- **Модалки — `createPortal` в `document.body`**, иначе обрезаются скроллом.
